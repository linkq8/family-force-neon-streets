# دليل حماية مفتاح توقيع Release

لا يحتوي هذا الملف على مسارات فعلية للمفتاح أو كلمات مرور أو قيم سرية. لا تنسخ
المفتاح إلى مستودع المشروع ولا إلى مجلد تسليم العميل.

## نموذج الحفظ الموصى به

- النسخة العاملة: مخزن مشفر على جهاز البناء، بصلاحيات قراءة للمالك فقط.
- النسخة الاحتياطية الأولى: وسيط مشفر غير متصل محفوظ في مكان آمن.
- النسخة الاحتياطية الثانية: خزنة أسرار مشفرة في موقع منفصل.
- كلمات مرور المخزن والمفتاح تحفظ في مدير كلمات مرور، منفصلة عن ملف المفتاح.
- الوصول محصور بصاحب المشروع وشخص استعادة معتمد عند الضرورة.

## إنشاء النسخ الاحتياطية

1. أغلق أدوات البناء وتأكد أن الملف الهدف هو مفتاح Release الصحيح بقراءة اسم
   alias وبصمة الشهادة فقط؛ لا تطبع كلمات المرور في الطرفية أو التقرير.
2. أنشئ نسختين مشفرتين عبر أداة النسخ الاحتياطي المؤسسية المعتمدة لديك.
3. سجّل تاريخ النسخ، المسؤول، بصمة SHA-256 للملف المشفر، ومكان الحفظ المنطقي.
4. لا تحفظ كلمة فك التشفير بجوار أي نسخة.
5. اختبر الاستعادة إلى مجلد مؤقت مشفر، ثم احذف النسخة المستعادة بأمان.

## اختبار الاستعادة كل 90 يومًا

استعد نسخة في بيئة معزولة، تحقق من alias وبصمة شهادة التوقيع، وقّع APK اختباريًا،
ثم تحقق منه بأداة `apksigner verify --print-certs`. قارن بصمة الشهادة بالسجل
المعتمد. لا تستخدم بيانات عميل حقيقي في الاختبار.

## سجل البناء

لكل إصدار احتفظ برقم الطلب، applicationId، رقم الإصدار، SHA-256 للـAPK، وبصمة
شهادة التوقيع. لا يسجل السجل كلمة مرور أو محتويات مفتاح أو متغيرات البيئة السرية.

## عند الاشتباه بالتسريب

أوقف البناء، اعزل جهاز البناء، احفظ الأدلة والسجلات دون نشر الأسرار، وراجع من
وصل إلى المفتاح. لا تستبدل المفتاح عشوائيًا: تغيير شهادة التوقيع يمنع تثبيت تحديث
فوق APK السابق. جهّز تطبيقًا جديدًا باسم حزمة جديد وشهادة جديدة فقط بعد تقييم
الحادث وخطة انتقال واضحة.

## قائمة فحص شهرية

- المفتاح غير موجود في Git أو `dist/` أو نسخ العملاء.
- صلاحيات ملف النسخة العاملة ما زالت محصورة.
- النسختان المشفرتان قابلتان للوصول ولم تتلفا.
- مدير كلمات المرور وحساب الخزنة يستخدمان MFA.
- لا تُطبع الأسرار في CI أو تقارير البناء.
